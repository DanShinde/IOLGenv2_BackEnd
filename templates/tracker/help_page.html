Getting Started: A Typical Workflow

Welcome to the Project Tracker! This application is designed to bring clarity, accountability, and real-time insights to your project management process. This guide will walk you through a typical project lifecycle from creation to analysis.

Step 1: Create a New Project

All work is organized by project. To begin, navigate to the Add New Project page. You will be asked to fill in a few key details that form the foundation of your project record: the Project Code (a unique ID), the Customer Name, its financial Value, the SO Punch Date (the official start date), and the business Segment it belongs to. A project created from the Planner's Add Project form collects the same details and creates the matching Tracker project too, so a project always exists in both places.

Step 2: Update Progress on the Detail Page

The Project Detail Page is your primary workspace for managing a project's progress. Here, you'll find lists of predefined stages. The core workflow is to set a Planned Date for each stage, update its Status as work progresses, and critically, enter the Actual Date of completion. This data is the engine that drives all the performance metrics and reports in the application. A few rules keep that data trustworthy — see Stage Dates & Handover, Delay Reasons and Phases.

Step 3: Monitor with the Dashboard

The Dashboard offers a high-level "mission control" view of your entire portfolio. It's designed for daily check-ins to monitor key health indicators, spot long-running "chronic" projects that may need attention, and review the pipeline of recently created work.

Step 4: Analyze with Reports

The Reports Page is your tool for business intelligence. It allows you to "ask questions" of your project data. By combining various filters, you can uncover trends, identify systemic delays, and generate targeted data sets for meetings and strategic planning. Any report you generate can be instantly exported to PDF.

The Dashboard

The dashboard is your main landing page, designed for at-a-glance monitoring of the entire project landscape. Use the date filters at the top to focus on a specific period, such as "This Month" or a custom date range.

Chronic Projects & Recently Created Projects

These tables automatically highlight important projects. The "Chronic Projects" table is particularly useful for identifying projects that may be stalled or forgotten, while the "Recently Created Projects" table shows the latest additions to the portfolio. Both tables feature live column filtering to help you find information quickly.

  • How it Works: To quickly find an item in either table, simply type into an input field located directly below a column header (e.g., "Filter Code..."). The table will instantly update as you type to show only matching rows, without needing to reload the page.

Projects List

While the dashboard provides a summary, the "Projects" page is the complete, unfiltered repository of every project in the system. It serves as the single source of truth for all projects, regardless of status or age.

Live Column Filtering

The most powerful feature of this page is the live filtering. Use the input fields at the top of the table to instantly search the entire project database. You can even combine filters. For example, to find all "In Progress" projects for "ABC Corp", type "ABC Corp" in the Customer filter, and then type "In Progress" in the Status filter. The list will narrow down with each keystroke.

Project Detail Page

This is the central hub where all detailed work on a single project is managed and tracked.

Project Timelines & Stages

The graphical roadmaps provide a quick visual summary of a project's progress. The solid green progress line is a key indicator, as it only advances to the last consecutively completed stage, giving you a true picture of committed progress. Below the timeline, the tabs for Automation and Emulation are where you perform the actual updates. If the project has several phases, each phase has its own tab with its own timelines and stage tables — see Phases.

Project Summary & Key Metrics

This card gives you a vital snapshot of the project's health. It includes schedule variance and two distinct OTIF (On-Time In-Full) metrics:

  • Overall OTIF % (All Stages): Think of this as the project's "term grade." It looks at every stage completed so far and calculates the percentage that met their planned deadline. The Dispatch and Handover stages are deliberately left out of this figure (and of every other OTIF % in the app): Dispatch is only used for the Emulation Timing Analysis on the Reports page, and Handover is judged separately by Project OTIF (Handover), which is unaffected. With several phases, the stages of all phases are counted together.
  • Project OTIF (Handover): Think of this as the project's "final exam." This metric focuses only on the final delivery and answers one question: was the project handed over on or before the promised date?
Recent Activity

This card provides a real-time feed of the last five changes made to any stage within this project. It shows what was changed, the old and new values, who made the change, and when it happened. For a complete audit trail, click the "View All" button in the corner to navigate to a page with the full, unabridged history for the project.

The full activity history page displays a detailed timeline of every change, as shown below.

Reports & Analysis

The reports page is the business intelligence hub of the application. It's designed to help you answer complex questions about your project data by building specific queries through multiple layers of filters.

A Multi-Layered Filtering Workflow Example

Imagine a manager asks: "Show me all high-value 'AMR' projects started this year that are currently on hold." Here’s how you would use the tools:

  1. First, use the main "Filter Options" panel. You would select "AMR" from the Segments list, set the "SO Punch Date Range" for the current year, and set the "Value Range" Min field to "10".
  2. Then, in the "Stage Specific Filters", find the row for a relevant stage and select "Hold" from the status dropdown. Click "Apply Filters".
  3. The table now shows your specific dataset. If the list is still long, you can use the Live Column Filters to narrow it down further.
  4. Finally, you can click on any project row to expand its Collapsible Summary and view its key stats without leaving the page.
Good to Know
  • Dispatch and Handover are not rows of the Stage-wise Planned vs Actual Summary, so they are not in its totals either, and neither is counted in any OTIF % (the Overall OTIF %, the OTIF trend and the dashboard's Department OTIF %). Dispatch is used only by the Emulation Timing Analysis chart at the bottom; Handover is judged by Project OTIF (Handover).
  • The Delay Reasons section at the bottom of the page explains why stages finished late — see Delay Reasons.
  • In projects with several phases, every phase's stage is counted separately in the stage tables and charts, so a two-phase project contributes two Offline Development stages. The Emulation Timing Analysis treats each phase as its own data point.

Stage Dates & Handover

A few rules keep stage data consistent. They apply on the Project Detail page whether you edit a field directly (it saves automatically) or use Save Stage / Save All.

Finish date and "Completed" go together
  • Entering an Actual Finish Date marks the stage Completed automatically. There is no separate step.
  • You can't mark a stage Completed without a finish date. The system will ask you to enter the date first; it no longer fills in today's date for you.
  • Changing a stage away from Completed (for example back to In Progress) clears its finish date.
  • You can't clear the finish date of a Completed stage. Change the status instead.
  • With Save All, any row marked Completed without a finish date is skipped and named in the message; the other rows still save.
A late finish needs a reason

If the finish date is later than the planned date, you are asked for a delay reason before anything is saved. See Delay Reasons.

Handover closes the project
  • Handover is the project's single closing stage. It can only be completed once every other stage is Completed or Not Applicable — in every phase. If something is still open, the message lists what.
  • The project shows as Completed when its Handover is Completed. Completed projects can't get new phases.

Delay Reasons

Whenever a stage is finished later than planned, the team records why. This turns delay dates into a picture of what is actually costing us time.

Recording a reason
  1. Enter the Actual Finish Date (or change the planned date) so that the stage ends up late. A Delay Reason popup opens.
  2. Click one or more reason tags. The standard ones are: Automation Resource Unavailability, Customer Dependency, Internal Dependencies (AD), Design Issues (Mech.), Design Issues (Elect.), Material Shortage and Incomplete IQ.
  3. Not listed? Type a new reason into Add a new reason… and click Add — it becomes a tag everyone can use.
  4. Optionally add a description, then click Save.
  • Nothing is saved until you save the reason. The finish date and Completed status are committed together with it. Refreshing the page mid-popup loses nothing that was on record.
  • Cancel throws the change away: the field goes back to what was saved and you re-enter it if you still want to.
  • At least one reason is required to save.
Adding or editing a reason later

Open a stage's Actions menu and choose Delay Reason at any time to add, review or change its reasons — handy for older delays that were recorded before this feature existed.

In the reports

At the bottom of the Reports page, the Delay Reasons section has a pie chart and table by reason: total delay days, number of stages and share. Click a slice, or View Detailed Delay Report, to see each delayed stage with its project, reasons and description. It follows the report's filters and date range.

Managing the reason list

Staff can rename or delete reasons in the admin site under Tracker → Delay reason tags, which also shows how many stages use each one. Renaming updates every past record; deleting removes that reason from the stages that used it, so prefer renaming.

Phases

A project delivered in stages over time — for example Zone A in January and Zone B in September — can be split into phases. Each phase has its own copy of the stage list, so finishing Phase 1's Offline Development doesn't wait for Phase 2's.

A project with a single phase looks exactly as it always did: phases are never mentioned until you add a second one.

Adding a phase
  • Click Add Phase on the Project Detail page and describe the zone the new phase covers (optional). The first time you split a project you can also describe the existing scope, which becomes Phase 1.
  • The new phase gets a fresh copy of every stage with blank dates. Handover is not repeated: it stays a single project-level stage.
  • A project that is already Completed can't get a new phase.
The Project Detail page with phases
  • The Phases table shows each phase's zone description, status, % complete and OTIF %. Use the pencil to edit a zone description at any time.
  • Each phase has its own tab with its own Automation and Emulation timelines and stage tables. Save All inside a tab only saves that phase.
  • The Handover row sits under the tabs, so it stays visible whichever phase you're viewing.
  • Next Automation / Emulation Milestone and the Automation / Emulation Schedule (days ahead or delayed) are shown phase by phase, with Handover on its own line. The same per-phase schedule appears in the Reports project rows, and a phase label is added to stage names in report drill-down lists, the Project Activity log and the milestone exports.
  • A phase can be deleted with the bin icon only if it isn't the last phase and none of its stages has progress. Deleting it also removes those stages' history, remarks and delay reasons.
How the numbers behave
  • Completion % is still the average over all applicable stages, so adding a phase lowers it straight away (its new stages start at 0%). Dashboard and report health colours follow that figure.
  • Project status becomes Completed only when Handover is completed, which in turn needs every phase's stages done.
  • OTIF is judged per stage, so each phase's stages count on their own; the project-level OTIF blends all phases. Project OTIF (Handover) still looks only at Handover.
  • The Dashboard and Reports count each phase's stage separately (counts can exceed the number of projects), and a phase's dates land in its own months. A project stays "live" until Handover, even if an early phase was delivered long ago.

Upcoming Milestones

A single list of stages by planned date, with filters for Overdue, Today, Tomorrow, This/Next Week and This/Next Month, plus Team Lead and Segment.

  • The date-range filters (Today through Next Month) show every stage planned in that range, including ones already completed, so you can see the full plan for the period. Overdue and All list only open stages.
  • For projects with several phases, each stage carries its phase badge.
